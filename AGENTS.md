# Edonism — Engineering conventions

## Scope and architecture
- This is a PvP-first browser city strategy game. Do not invent canonical rules before reading user-supplied game design documents.
- Backend .NET 10: `src/backend/domains` (deterministic rules/aggregates), `business` (use cases), `infrastructure` (adapters), `applications` (HTTP/SignalR surface).
- Frontend React + TypeScript + Vite: `src/features/city` is the 3D scene (Three.js + React Three Fiber), `src/components/ui` is shadcn/ui and DOM app chrome. The **original printed street graph** and 30 activity lots are described in `src/shared/board/edonism-board.v1.json` (issue #5); axial hexes are NOT gameplay coordinates. Do not mix visual preview with authoritative gameplay state.
- Future PvP/economy state MUST be validated and applied server-side. Clients submit intentions, not trusted game outcomes.
- Prefer deterministic generation (explicit seed + version) and maintain auditability for any money, ownership and PvP transitions.
- The board graph and slot IDs are data-driven and shared between .NET and React. Never derive movement from preview geometry or pretend the source document defines unapproved PvP rules.

## Mandatory issue workflow
1. Inspect current repository, tests, docs, `docs/engineering/development-ledger.md`, and existing GitHub Issues.
2. Create/claim an issue with goal, scope, acceptance criteria, target version and test plan before coding.
3. Set ledger status to In progress. The game designer currently requests **direct commits on `main`**; keep each commit linked to a GitHub Issue and run CI after every code batch. If this workflow changes in future, use a branch/PR without bypassing issue tracking.
4. Test with xUnit for backend rules and Playwright for visible frontend behavior, including mobile, language and theme.
5. Do not close issues until relevant tests and CI (on `main` for direct commits) are green, docs and patch notes updated, and a closure note recorded. Fix CI failures before starting the next feature.
6. Keep `VERSION` as release source of truth, update `docs/patch-notes/` for release changes.

## Frontend conventions
- React Three Fiber v9 / Three.js: scene input, 3D objects and camera only.
- shadcn/ui + Tailwind semantic tokens: navigation, HUD, cards, selectors, forms and modal surfaces.
- Theme: `system`, `light`, `dark`; persist choice in localStorage.
- i18next Italian and English, no new hard-coded UI strings.
- Accessible equivalents for important canvas interactions: controls outside WebGL are keyboard-operable.
- No externally owned/third-party art in final assets. Code-generated geometric placeholders are acceptable.
- The Development-only match laboratory is under `src/features/matches` (#20), hidden by `import.meta.env.DEV`. Do not expose its creator-issued all-seat tokens or synthetic catalog through Production, URLs or localStorage; real PvP authentication belongs to #13.
- The public-only match-to-city marker projection (#22) lives under `src/features/city/playerMarkers.ts`; it receives only player IDs, street IDs and the current actor. Its X/Z values are view placement on existing road rectangles, never Domain movement coordinates. Keep an accessible roster for WebGL fallback.
- Activity and henchman visuals (#23) use `src/features/city/activityMarkers.ts` and only public `boardActivities`, `controlledActivities`, and `grossSalaryQuotes`. Never infer ownership from position or award gross salary in React; cardinality/owner/posture validation must fail closed, and keep a WebGL-free roster.
- The first-round public audit verifier (#24) lives in `Edonism.Domain.Matches.MatchAuditReplay`: only the existing four event kinds are supported. Update the verifier and its tamper tests before adding new Domain audit kinds. The browser's `publicAudit.ts` whitelist is display-only and must never become authority. Do not claim that a verified movement log is persisted game restoration, salary/election settlement, or Production authorization.
- Test fallback and narrow screens, avoid requiring WebGL for critical interactions.
- For interactions that cross React → ASP.NET Core (match commands, private projections, reconnect), use **both** fast mocked Playwright UI tests and the real API suite `npm run test:e2e:live` (requires backend Development on loopback). GitHub Actions runs all three gates (xUnit, UI, full-stack). Never claim mock-only browser tests prove API behavior.

## Backend conventions
- Keep Domain independent from ASP.NET Core, EF and serialization frameworks.
- No DB or migration until the game rules define aggregates and persistence requirements.
- No client-authoritative ownership, currency or PvP.
- Compile with nullable enabled and warnings as errors; xUnit for deterministic tests.

- The two-browser Development lab (#25) uses an in-memory single-seat join (match UUID + bearer token) and server-authenticated polling. No token in URLs, logs, localStorage/sessionStorage or React's public 3D projection. Never treat the creator's all-seat credentials or clipboard access as Production identity. Gate all Dev routes and this lab from Production; test real browser isolation, monotonic revisions and 409 reconciliation.

- Encrypted Development checkpoints (#26) are opt-in, single-process and NEVER Production persistence. The Domain checkpoint contains secret action hands/draw pile: never return it from APIs, logs, telemetry, browser JSON or fixtures committed to Git. Store only SHA-256 of 256-bit random bearer tokens inside AES-256-GCM ciphertext. Changing event kinds/phase/quotas requires a version bump and restore validation/tests; do not imply public audit replay #24 alone can restore secret state. Keep keys out of Git; do not enable this mode by default in CI.

- The Development match lab's 2–8-seat fixture (#27) must keep synthetic character starting activities within each printed activity category quota **for any sampled subset**; the server is still authoritative for character draw, street placement and turns. Test multi-seat privacy and mobile/i18n in mock Playwright plus 8-seat first-round progression and single-token join against real .NET live E2E. No Production account or real card metadata is implied.

- Dev seat-token rotation (#28) is capability-based, NOT Production identity. Only the current 256-bit token in the request header may rotate its seat; never accept a client playerId. Persist the new digest first under the match lock before invalidating the previous digest. Rotation MUST NOT mutate the game revision, history, hand or public scene. Never expose credentials via URL, logs or storage; return only one seat token with no-store. Test failure rollback, post-restart revocation, concurrent rotation, mock UI and real multi-browser Playwright.

- Turn options (#29) are **read-only actor-scoped projections** computed by the .NET Domain from its canonical street graph and current revision. The React Development lab may translate server-returned street IDs into labels, but may neither infer permission from local geometry nor enable commands when a revision, player, token or match differs. After polling, seat switch, token rotation or 409, refresh options; a missing response must fail closed. This is NOT an action-card effect, round-settlement mechanic or Production action API.

- Conditional Development snapshot polling (#30): always authenticate the per-seat token before returning a revision ETag or 304; no 304 to anonymous/revoked/malformed credentials, no private state in the tag, and no Production routes. The browser may send `If-None-Match` only for its current match, current in-memory token and confirmed revision; 304 must not parse JSON or update game state. A changed revision forces a full 200; refresh on foreground/online and stop network polling while hidden. Gate with xUnit + mocked and real-API Playwright.

- Client-side Development revocation reconciliation (#31): 404 from a previously authenticated seat's snapshot/hand/options/command indicates that **exact bearer and seat** is no longer valid (or the Dev match is gone). Clear that seat's hand, legal options and in-memory ETag; if creator holds other seat capabilities, keep them and select a valid one, otherwise clear the match UI and ask for a fresh token. Ignore delayed 404s from old actor scopes. Do not treat 503, offline or 409 as revocation, or claim UI clearing erases knowledge already seen by users. Test mocked browser races and actual two-browser .NET rotation/rejoin.

- Atomic Development seat bootstrap (#32) is `GET /api/dev/matches/{id}/seat`: the .NET store must resolve actor from the current token and capture public snapshot, **only that actor's private hand**, and same-revision Domain turn options under the **same lock**. Never trust query playerId or return bearer tokens, deck or checkpoints. Respond no-store; unauthorized/revoked -> 404. Browser join must validate match, actor and revision agreement **before** installing a session; skip initial redundant hand/options fetches, but retain subsequent polling, revocation reconciliation, revision checks and no browser persistence. Test with xUnit HTTP/concurrency/checkpoint and mocked+live Playwright. This is not Production login.

- Development response cache privacy (#33): all routes under `/api/dev/matches`, including **all four creator issuance paths** containing 256-bit bearer credentials, actor-private hands, joined seat bootstrap, audit, moves, rotation, conditional 304 and **all** errors, must emit HTTP `Cache-Control: no-store`, `Pragma: no-cache`, `Expires: 0`. Enforce once in the Development-only ASP.NET Core middleware, both before `next()` and in `Response.OnStarting` to survive model-binding failures whose error pages clear earlier headers. Do not depend on per-endpoint settings or client fetch cache policy. Never put bearer secrets in HTTP headers or telemetry. Avoid affecting public board/meta/health or adding Dev routes in Production. Test all status codes with WebApplicationFactory and real Playwright, not only mocked browser responses.

- Authenticated Development conditional long polling (#34): a `GET /api/dev/matches/{id}` with an exact current `If-None-Match` and `Prefer: wait=1..10` registers a bounded, cancellable waiter under the **same match lock** used for moves, end-turn and token rotation, then waits **outside** that lock. Signal all subscribers asynchronously only after a committed command or successful token rotation; remove waiter on timeout, cancellation or signal to prevent idle-match memory retention. Wake must recheck the bearer before either 304 or a newer 200; revoked -> 404, no revision changes on token rotation, all results no-store. Invalid/unmatched/wildcard tags or invalid wait preferences must not block. React sends the preference only with an actor/token/revision-bound ETag; cancel pending long poll when the tab hides or actor/match changes, restart on focus/online and fall back to normal polling on errors. Development-only single process; **not** a Production event service or rule implementation.

- Idempotent first-round Development commands (#35): `POST /api/dev/matches/{id}/free-move` and `/end-turn` may include the optional header `Idempotency-Key` (nonempty UUID in D format). Scope accepted receipts to **match + authenticated actor + UUID** and match exact command, destination and `expectedRevision`; same input replay returns 200 with the **current authoritative snapshot** and no extra event, revision or long-poll signal; same key with changed input returns 409. Resolve bearer first: revoked credentials always 404 even with a known key. Old clients without a key retain 409 on stale revision. Never store tokens or hands in receipts, URLs, logs or Web Storage. Cap receipts at 64 per Development match; a replay beyond retention may be rejected with 409, never double-apply. For optional AES-256-GCM storage, commit accepted Domain state AND receipt **in one encrypted checkpoint** before publication and wake-up, fail closed on I/O error. The trusted Development checkpoint plaintext metadata is v2; safely load historical v1 with no receipts, upgrade on next successful write and validate receipt-to-audit consistency before restore. React retries exactly once with the same UUID ONLY for a network/transport exception, not for HTTP errors; never infer a successful turn or change actor on a lost ACK. Test xUnit concurrency/rollback/legacy restore and mocked+real API Playwright.

- Development long-poll capacity and PvP fairness (#36): the match store limits authenticated conditional waiters under the match lock to **4 per actor and 32 per match**; check bearer authorization and current revision *before* attempting reservation. Invalid/revoked bearer remains 404; an actor at quota receives a fast 429 with `Retry-After: 1` and server-wide no-store, NO ETag/hand/secret. Other actors must still wait/read/command. Remove each waiter on cancellation, timeout, accepted command or token rotation, without holding the lock during await. Ordinary authenticated snapshots, wrong-ETag and no-Prefer GET never consume wait slots. React treats 429 as transient congestion, keeps its hand/ETag/revision and polls normally for a bounded five-second cooldown rather than retrying the congested waiter. All this remains single-process Development, not Production rate-limiting; keep xUnit and mocked+real Playwright regression coverage.

- Verified public first-round history (#37): the .NET Domain `MatchAuditReplay.Verify` produces revision-aligned *immutable copies* of every public first-round frame, starting at genesis; on any tampered audit/snapshot it returns **zero frames**, not a partial replay. A frame contains only revision, event kind/actor, phase, active player and all 2–8 public positions/free-move flags; never token, deck, hand, character secret, economy or hidden action. Authenticated Development `GET /api/dev/matches/{id}/history` returns only successfully verified frames under one match lock, with #33 no-store, 404 anonymous/revoked and no Production route. React's history inspector is separate read-only UI: it rejects malformed/stale/wrong-seat history, uses prev/next/latest buttons and IT/EN text, and never projects historical coordinates into 3D live markers or enables commands on an old revision. Test Domain tampering and 2–8-player histories, WebApplicationFactory auth/no-store, Playwright mobile mock and real two-browser flow. Full replay of private gameplay or future rounds requires #4/#6; this slice is NOT a Production spectator service.

- Development PvP seat presence (#38): `DevelopmentMatchStore` exposes **ephemeral, bearer-scoped** `POST /api/dev/matches/{id}/presence` (heartbeat) and `GET /presence` (read-only) only in Development. The server derives the actor from the current bearer under the match lock and stores **at most one last heartbeat per actor** with an injectable `TimeProvider`. An actor is recently active for **strictly less than 15 seconds**; no timestamp, bearer, digest, hands, deck, client identity, exact connection count or game state is in the presence DTO. GET must not refresh presence. Token rotation resets only the rotated actor's presence **after checkpoint persistence succeeds**. No heartbeat writes encrypted files, changes revision/audit/turn/legal commands or wakes a long poll; presence is empty after restart. Invalid/revoked bearer always 404, never an API snapshot or impersonation from query/body playerId, with no-store policy #33. React emits one POST roughly every 5s only when visible and online, no overlapping requests, aborts stale requests on actor/token/match switch and background/offline, verifies all server-returned IDs and booleans, renders accessible IT/EN recent/inactive/unknown labels. A 503/offline response is 'unknown' only, never revocation or a turn permission. Real login/SignalR/multi-instance pubsub belong to #13; heartbeat is NOT proof a person is connected.

- Voluntary Development browser exit (#39): show an IT/EN accessible leave control only with a session.
